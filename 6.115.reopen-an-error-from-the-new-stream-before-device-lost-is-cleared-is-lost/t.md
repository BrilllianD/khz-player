# Reopen: an error from the new stream before device_lost is cleared is lost

Re-review of 7cd2827 (slice 1.1, task 113 fix wave). AudioHandle::reopen (src/audio/mod.rs:119-123) now clears device_lost only after output::open returns, so the stall watch stays disarmed during a slow open. Side effect: if the new stream reports an error between stream.play() (src/audio/output.rs:94) and the store(false), the callback's swap(true) sees true and the clear then wipes it. While playing, the stall watchdog catches the dead stream after STALL_TIMEOUT (1 s); while paused or stopped it goes unnoticed until playback starts and stalls for 1 s. Possible fix: clear device_lost before open as before and reset the StallWatch in Engine::set_output, or add a separate reopening flag that check_stall honours. Low impact; do it when touching src/audio/ next (e.g. task 105).
